# Architecture and tradeoffs

Engineering selection: React/TypeScript/Vite, Express, TypeORM and SQLite through the `sqljs` driver. TypeORM EntitySchema and repository adapters isolate ORM details from domain services; business rules depend on a repository/unit-of-work interface shared with the earlier in-memory adapter. TypeORM migrations are versioned and run explicitly; production schema synchronization must be disabled.

SQL.js produces an actual SQLite database file with configured autosave and avoids native compilation requirements. It is an embedded single-process solution: serialized mutations, transaction boundaries and durable export must be verified; it is unsuitable for multiple application instances without redesign. Compare alternatives: native SQLite driver gives direct durable writes but requires compatible binaries/build toolchain; PostgreSQL improves multi-instance concurrency but violates the assignment's chosen SQLite storage requirement. ORM portability is a design property, not a claim that every database engine is already tested.

Domain models: User (customer/workshop/admin), WorkshopProfile (approval), RepairRequest, Photo, Offer, QuoteVersion, ActivityEvent, Session. Requests own offers/photos/events; offers own immutable quote versions. Request references at most one selected offer and accepted version. Repository updates use expected version/state checks and a transaction for selection, quote acceptance/rejection and repair transitions. Unique active offer/workshop/request must be enforced transactionally and with appropriate database constraints. Awaiting-revision state blocks repair; immutable accepted versions remain available in history.

Authentication uses hashed passwords (scrypt with per-password salt), opaque server sessions in HttpOnly cookies, server-side role/ownership checks, CSRF protection for cookie mutations, expiry and sign-out. Admin is seeded explicitly through environment values and never public signup. Server projections expose only authorized request/contact/offer fields. Photos are stored privately, restricted to three 3-MB files, signature/type validated and served only through authorized routes. Do not expose static upload directories.

API contract in `openapi.yml` precedes backend code. Money is nonnegative integer minor units, currency KZT. Nullable unknown fees stay distinct from zero; comparisons separate known subtotal, optional amounts and unknown/excluded charges. Fixed offers require complete pricing. Errors use consistent structured code/message/field details, 401 unauthenticated, 403 unauthorized, 404 inaccessible resource where appropriate, 409 lifecycle/concurrency conflicts and 422 validation.

Iteration sequence and source deviations are documented in `process.md`. Actual package versions and executed migration/persistence evidence must be recorded by the engineer, not assumed in this preimplementation specification.
